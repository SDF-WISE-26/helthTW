# Monitoring on the VMs

- **Status:** accepted · **Date:** 2026-11-10, Beszel 2026-11-19 · **Involved:** @Lezhor, @LilGravyyyy · **Ref:** #152
- **Decision:** Dozzle shows container logs and resource use on the prod-vm. Beszel keeps about 30 days of CPU, memory, disk and network for both VMs and the prod-vm's containers: the hub on the prod-vm, an agent on each VM. Everything runs as its own Compose project in `/srv/monitoring`, apart from `deploy.sh`, and the web pages only listen on `127.0.0.1`. Devs reach them through an SSH tunnel as the user `monitoring`: keys only, added by an admin, and nothing allowed but tunnels to the monitoring ports. Dozzle has no login, Beszel logs everyone in as a read-only user. Docker is only reached through socket proxies that let reading requests through, Beszel's without container details. The hub dials the ops-vm's agent over SSH, which the firewall only allows from the prod-vm. Images are pinned by digest, analytics and update checks are off. Setup in [`deployment.md`](../deployment.md#monitoring).
- **Why:** The logs may contain health data. SSH already limits who can reach the VM, so there is no extra password and the only firewall change is the hub's path to the ops-vm. Devs need no account of their own on the VM. Access to the Docker socket is effectively root: through the proxies, a compromised tool can read, but not start, stop or exec into containers. Container details would show every container's environment, including the database password. A broken monitoring setup cannot block a deploy.
- **Rejected:** A port for the HTW network with a login for Dozzle and Beszel, e.g. through Caddy (firewall change, passwords to manage, login pages for all of HTW). Personal Beszel accounts (a second gate behind the tunnel, Dozzle would have none). Beszel agents dialling the hub over WebSocket (the hub's page would have to listen beyond `127.0.0.1`, open to the ops-vm, where every workflow runs). Dozzle on the ops-vm (no long-running containers, the runner logs to journald). An account on the VM for every dev (more rights than reading logs). Mounting `docker.sock` read-only (`:ro` only protects the file, not the API behind it). Dozzle Cloud or a hosted service (data leaves the VM). A stack like Loki, Prometheus and Grafana (several services and storage for a prototype).
- **Caution:** Dozzle only shows what Docker keeps (3 × 10 MB per container), there is no history. Every key on `monitoring`'s list can read all logs, remove keys of people who leave. Everyone who can log into the prod-vm can open both tools too. Never connect Dozzle Cloud, never turn on Beszel's container details. Beszel has no alerts. Changes to `deploy/monitoring/` are installed by hand, a release does not do it.
